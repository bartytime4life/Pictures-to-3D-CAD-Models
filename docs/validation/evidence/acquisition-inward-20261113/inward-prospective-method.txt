## A componentwise rounding budget

For a nonzero positive span `s_j`, use exact rational bounds and upward binary64
ceilings. Let `ulp` mean a full unit in the last place, including the smallest
subnormal at zero. Define

```text
u_p = ulp(max(abs(actual_lower), abs(actual_upper), abs(anchor))),
D = max(abs(F(actual_lower)-F(anchor)), abs(F(actual_upper)-F(anchor))),
u_s = ulp(ceil_binary64(D)),
u_d = ulp(ceil_binary64((D+u_s)/F(span))),
rho = u_p/F(span) + u_s/F(span) + u_d,
M = (D+u_s)/F(span) + u_d.
```

The full physical ULP covers either adjacent bracket endpoint while the target
and endpoint remain within the original physical domain. The subtraction and
division terms account for computing `(physical-anchor)/span`. These bounds
assume recorded IEEE binary64 nearest rounding and gradual underflow. Every
bound and comparison uses guarded rational arithmetic; overflow, nonfinite
upward ceilings or a bit cap withhold the construction as unknown.

An original normalized-box side receives margin `rho_j`; an added physical
side receives `u_p_j`. For a source row, begin with `sum |G_ij| rho_j` and add
full-ULP product allowances using `w_j = |G_ij| M_j`, plus two ULPs of the
upward bound `|z0_i| + sum_j(w_j + product_allowance_j)`.
Exact-zero products need zero allowance.
The final sum allowance is an **engineering proposal margin**, not a global
theorem about every `math.fsum` implementation. Python documents possible
double rounding. All five original candidate gates remain independently
decisive; no tolerance turns an outside point into a pass.

